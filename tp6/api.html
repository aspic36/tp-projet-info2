1. Dépôt de données et requêtes préparées

DemandeRepository expose des opérations nommées ; aucun contrôleur n'écrit de SQL. Toutes les valeurs passent par des paramètres liés.

public function findById(int $id): ?array
{
    $stmt = $this->pdo->prepare(self::SELECT_BASE . ' WHERE d.id = :id');
    $stmt->execute([':id' => $id]);
    $row = $stmt->fetch();
    return $row === false ? null : $this->normaliser($row);
}

2. Table des transitions et refus 409

public const TRANSITIONS = [
    'BROUILLON' => ['SOUMISE'],
    'SOUMISE'   => ['VALIDEE', 'REFUSEE'],
    'REFUSEE'   => ['BROUILLON'],
    'VALIDEE'   => [],
];

public static function peutPasser(string $de, string $vers): bool
{
    return in_array($vers, self::TRANSITIONS[$de] ?? [], true);
}

Le service vérifie aussi qui peut effectuer la transition :

SOUMISEétudiant propriétaire uniquement
BROUILLONétudiant propriétaire (correction après refus)
VALIDEE
REFUSEE		responsable pédagogique uniquement

Une cible inconnue renvoie 400 ; une transition non listée renvoie 409 sans aucune écriture.

3. Connexion et session

if (!password_verify($password, $row['mot_de_passe'])) {
    // message identique à celui d'un compte inconnu
    throw new ApiException(401, 'Identifiants incorrects.');
}
session_regenerate_id(true);            // empêche la fixation de session
$_SESSION['user_id'] = (int) $row['id'];

Les mots de passe sont stockés en bcrypt (password_hash, coût 12) ; le message d'échec ne distingue pas un compte inconnu d'un mot de passe faux. Le cookie de session est HttpOnly et SameSite=Lax.

4. Transaction de validation

$pdo->beginTransaction();
try {
    $courante = $demandes->findByIdForUpdate($id);        // 1. verrou + statut courant
    if (!peutPasser($courante['statut'], $cible)) {        // 2. contrôle de transition
        throw new ApiException(409, 'Transition interdite…');
    }
    $demandes->updateStatut(...);                          // 3. UPDATE demande_stage
    $historique->add($id, $courante['statut'], $cible, $user['id'], $motif); // 4. INSERT
    $pdo->commit();
} catch (Throwable $e) {
    $pdo->rollBack();                                      // aucun état partiel
    throw $e;
}

Si l'insertion d'historique échoue, le rollBack() annule aussi la mise à jour du statut : la base reste dans son état antérieur.
