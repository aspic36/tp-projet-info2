Installation, exploitation, sauvegarde et restauration

Windows 11 · PHP 8.3.33 · MySQL 8.4.3 · mysqldump 8.0.46 · 18 / 11 / 2026

Le TP9 vérifie qu'une troisième personne peut installer l'application à partir du seul dépôt, puis qu'une perte de données peut être annulée sans intervention manuelle. Les trois opérations sont outillées par des scripts versionnés dans tp9/scripts/. Procédure complète : tp9/installation.md.

2. Compte applicatif et moindre privilège

SujetRéalisation
Comptestages_app, mot de passe propre au poste, distinct du compte administrateur MySQL.
DroitsSELECT, INSERT, UPDATE, DELETE sur stages et stages_test. Aucun DROP, ALTER, CREATE : le schéma ne peut pas être modifié par l'application.
SecretsMot de passe uniquement dans .env, ignoré par Git (preuve : tp4/preuves/git-ignore-env.txt) ; .env.example ne contient que changez_moi.
Scripts DDLExécutés par un compte administrateur, jamais par l'application ; procédure séparée en section 3 de installation.md.

3. Sauvegarde

$ powershell -ExecutionPolicy Bypass -File tp9/scripts/sauvegarde.ps1
Sauvegarde terminee
  fichier   : ...\sauvegardes\stages-20261118-154238.sql
  taille    : 16486 octets
  lignes    : 287
  sha256    : ADB50F13666266715D4BE91B94DDB6835694DA10280965170A255273B59E9840

Le dump contient les 7 tables, les 2 vues et toutes les données (8 utilisateurs, 4 demandes, 5 événements d'historique, 1 soutenance). Options retenues :

--single-transactioninstantané cohérent sans verrouiller les tables
--routines --triggerssauvegarder la logique serveur, pas seulement les lignes
utf8mb4aucune conversion d'encodage
sans --databasesle dump se recharge dans n'importe quelle base cible

L'empreinte SHA-256 sert de preuve d'intégrité : elle est recalculée avant chaque restauration. Une taille anormalement faible ou une empreinte différente signale une sauvegarde corrompue ou tronquée.

Le dossier sauvegardes/ est ignoré par Git : on versionne la procédure et les preuves, pas les données.

6. Exploitation courante

MécanismeUsage
/api/santeSELECT 1 sur la base : 200 si tout va bien, 503 sinon, sans exposer de détail technique. Preuves : tp4/preuves/sante-200.txt et sante-503.txt.
logs/app.logErreurs et événements datés (fuseau Africa/Porto-Novo) ; fichier ignoré par Git, jamais exposé par le serveur web.
Journal des transitionsLa table historique conserve auteur, statut avant, statut après, motif et horodatage : c'est la piste d'audit métier.
RythmeSauvegarde quotidienne (7 jours), restauration de contrôle hebdomadaire, archive mensuelle 12 mois.

7. Limites connues

  • Cookie de session en secure = false : à passer à true derrière HTTPS.
  • Dump non chiffré avant copie hors site.
  • Aucune supervision active de /api/sante : la sonde existe mais n'est pas interrogée automatiquement.
  • Pas de bascule automatique : la restauration est une opération manuelle et documentée.
